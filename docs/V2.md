# Wald-Q4B v2: C16B checkpoint selection

v2 starts from **C16B (`04400-c18`)**, the completed 125-step continuation of full-parameter C16 (`04000-c16`). It is a Qwen3.5-4B chat-lineage checkpoint. C16B and its parent are not the separate C16 LoRA arm (`040A0-c16`). The inference model SHA256 is `2859df99ed481592cdc3731fd768bf29ccd63273b2dab623642ad3b38b0e14c4`.

The checkpoint has completed evaluation and private weight verification. This GitHub update records the v2 selection and aggregate scores; public v2 weights and a compatible server have not been released. Existing v1.1/v1.2 downloads remain their documented releases.

## Serving contract for v2

C16B reasoning is native Qwen `<think>` generation on the same weights, with a pinned chat template, native512 budget, canonical option keys and final letter-probability recomputation. No additional thinking LoRA is loaded. The existing released server generates `Reasoning:` with the legacy plain prompt; pointing that server at C16B does not reproduce this evaluation.

Before a public v2 serving release, integrate and test the native prompt/template and probability mapping against the frozen reader, ship the matching calibration configuration, then measure the packaged API. Default v2 policy is still to be validated on the deployment task; the evaluation's primary policy is thinking off. No new paid training or GPU execution is started by this selection.
